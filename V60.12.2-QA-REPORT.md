## Source defects corrected

### Provider HTML encoding
The old synthetic provider route fulfilled UTF-8 text containing an em dash
with only `Content-Type: text/html` and no charset metadata. That left decoding
ambiguous for the exact Unicode heading used by eleven assertions. The new
test-only helper sets BOTH `text/html; charset=utf-8` and early `<meta charset>`.
The heading text is not replaced with ASCII and exact matching is not loosened.
The user's missing-heading root cause is source-supported; the precise decoded
Windows DOM would require its original trace/screenshot. That trace was not
attached. The new charset-specific browser cases are the confirmation gate.

### Logout response observation
The test read `response.json()` after the application had already replaced the
document. It now buffers the actual fixture/proxy HTTP reply using route.fetch
BEFORE fulfilling it to the browser, preserving upstream status, headers,
Set-Cookie and identical body bytes. Assertions still require status 200,
signedOut=true, one logout request, cleared session cookies and landing URL.
No production logout timing or security rule is altered.

### Back then Refresh synchronization
Tests now wait for the signed-out guest document and visible sign-in controls
before issuing Refresh. A still-protected URL is not accepted; the immediate
Logout assertion still requires exact root `/`. After Back, either guest
landing or sign-in is an allowed safe destination. No ERR_ABORTED is swallowed
and no assertion/test timeout was increased.

### Payment status alert
The error assertion is scoped to the existing `.checkoutReturnCard` and the
expected message. It still asserts exactly one matching alert. Next's
accessibility announcer remains intact; no arbitrary `.first()` hides it.

### Async order creation
Approval now waits for the synthetic provider document and finds the order by
THAT page's exact fixture ID and provider. It never selects list.at(-1) before
an asynchronous checkout POST has completed. The wait is read-only and creates
no order. A delayed-creation case is added.

### Reports and unchanged acceptance
The full suite declares 44 cases: all 41 original cases plus 3 extra cases.
The extra cases are Stripe/PayPal UTF-8 fixtures and delayed order creation.
JSON browser output is added at frontend/qa/ui-results.json.
Original single-order, invoice, amount, ownership, no-auto-retry, cookie,
hydration, paid-return and certificate no-reload assertions remain.
No tests skipped, `.only`, new retries or timeout inflation were introduced.
