# Singh Academy V60.11.1 — focused authentication follow-up

This is a **targeted patch to V60.11.0**, not a redesign or a claim of complete live-site verification. It addresses the origin-changing redirect shown in the supplied browser-test log and removes an enabled-before-hydration Logout control found in the source.

## What changed

1. `frontend/next.config.ts`: enable `skipMiddlewareUrlNormalize: true`. In Next 15.5.27 the middleware `NextURL` normalizer changes loopback IP hosts to `localhost`, and the response adapter can normalize a redirect's Location again. Preserving the raw middleware URL avoids switching a browser from `127.0.0.1:3108` to `localhost:3108` and losing its host-only session cookie. No cookie is broadened to another domain, and page/API authorization remains enabled.
2. `frontend/components/SiteHeader.tsx`: Logout and the mobile-menu button remain disabled until their component has hydrated. The server-rendered and first client-rendered markup both use the existing `useHydrated()` false snapshot. A synchronous Logout lock prevents two immediate clicks from starting competing UI actions. The existing AuthProvider still owns revocation, denial cookies and the single final logout navigation.
3. `frontend/ui-tests/auth-hydration-v60-11.spec.ts`: retain the original eight browser cases and their exact URL, cookie, timeout and hydration assertions. Add two cases for exact document redirect origin and delayed-JavaScript Logout readiness. No failed test was skipped, relaxed to accept both hostnames or given a longer assertion timeout.
4. Add fourteen executable focused control/config/middleware tests. Update the header-layout fixture to explicitly represent a hydrated header.
5. Application metadata, health/startup version and workspace version are now `60.11.1`. Dependency/override declarations are unchanged.

## Evidence and uncertainty

The user's V60.11 log shows an expected `http://127.0.0.1:3108/home` but received `http://localhost:3108/login?next=%2Fhome`. The Next 15.5.27 source confirms loopback URL normalization. `%2F` is normal percent-encoding for `/`; it is not a new route or a vulnerability and is intentionally retained in `next` query values.

The other failed browser case stayed at `/events` for the five-second assertion window. Its trace ZIP was not supplied. **The exact sequence of that user's Logout failure is not proven by the text log.** Source inspection did reveal an enabled SSR Logout button before its click handler was hydrated. This patch closes that real inert-click window; the browser rerun remains the acceptance gate, rather than declaring the observed failure solved solely from unit tests.

## Deliberately unchanged

- Public landing `/`; authenticated student entry goes to `/home`.
- Protected pages still require a verified session and retain safe post-login destinations.
- Explicit Logout does not automatically sign the student back in. Existing legacy-cookie clearing, server-side revocation, local logout fence and cross-tab behavior remain.
- Authentication is not replaced with a new library. Password-only admin policy remains as requested.
- Courses, per-user progress/answers/enrollments, membership terms, invoices, payments, email jobs and certificate records are not migrated, reset or seeded.
- Payment provider logic, idempotency and receipt verification are not altered.
- Public CSS, logo/images, footer layout and approved certificate artwork/renderer are unchanged from V60.11.0.
- Normal local ports remain frontend `3000` and backend `5000`. Browser-fixture ports remain `3108` and `5109` only.

## Installation

Use either the complete source ZIP or the small PATCH ZIP, not both.

### PATCH ZIP (fastest for a working V60.11 checkout)

Stop the old dev servers and any running browser test. Back up the working project. Open the patch folder and copy its contents over the existing **project root** containing `backend`, `frontend` and `package.json`.

Do not copy the patch as a new subfolder under `frontend`. Preserve your private `.env` files and the tested backend/frontend `package-lock.json` files. Never put secrets into chat or Git. No new database migration or seed command is needed.

### Complete ZIP

Extract `SINGH-ACADEMY-V60.11.1-COMPLETE`. Copy your working private configuration and tested lockfiles into the same relative locations. The source ZIP does not fabricate lockfiles or contain credentials/node_modules.

No `--force`, skipped tests, retries added to hide failures, new account seeds, or secret rotation are needed for this patch.

```

```

Open `http://localhost:3000`. Start with the existing browser, without clearing legacy cookies, then repeat in a private window.

Required checks: guest landing -> protected link -> credentials -> requested page; authenticated root/login -> home; Events -> Logout -> landing; Back/refresh -> no old account; autofilled login -> Back -> no login submission. Repeat Logout once under Slow 3G to check button-readiness and single-request behavior.

Do not redeploy Hostinger until the **actual browser suite** and your signed-in manual checks pass. A 200 health response alone is not sufficient. `api/health` identifies the backend; `api/app-build` identifies the frontend independently.
