## Enrollment-specific verification
- The course enrollment route does not intentionally return 409 for an already entitled/enrolled student; existing course access returns success.
- Duplicate-key race handling retains the existing enrollment when another request creates it first.
- Startup index repair removes the known legacy `courseSlug`-only or `user`-only unique indexes.
- V60.2 additionally rejects/repairs malformed exact `(user, courseSlug)` compound rules such as non-unique, sparse, partial, or non-simple-collation variants.
- The intended database rule remains one enrollment per student per course.
- Exact-boundary membership renewal is treated as continuous access.

## Packaging/release limitation
A full dependency-backed Next.js production build, TypeScript dependency typecheck and npm vulnerability audit were **not re-executed in this audit environment** because the supplied source did not include `backend/package-lock.json` / `frontend/package-lock.json` or installed dependencies, and npm registry network resolution was unavailable. The project intentionally keeps `npm run verify` fail-fast until those lockfiles exist.

On a normal development machine with npm access, run:

```bash
npm run install:all
npm run verify
```

Then perform browser acceptance against the real MongoDB/SMTP/payment-provider environment before production deployment.

## Scope statement
Passing automated tests and static checks reduces known regression risk but is not a guarantee that no defect can exist under every browser, production database state, third-party API response, network failure or deployment configuration.
