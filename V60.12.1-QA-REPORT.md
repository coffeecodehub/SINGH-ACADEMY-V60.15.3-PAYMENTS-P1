## Root cause verified in source

The old release checker unconditionally threw for `process.versions.node` major
other than 22 before creating `qa/release-checks.json`. All three source package
manifests also advertised only `22.x`. Thus the user's Node 24.18.0 run was refused
before installation, tests, database validation or payment configuration ran.

The new shared policy accepts stable `22.x || 24.x`, consistently across root,
backend/frontend manifests, install, verify and release gate. This is an allowed
runtime policy; **it does not claim the full application was executed here on
Node 24**. Old, odd-numbered, future unreviewed and prerelease families still fail.
There is no NVM dependency and no CLI flag to skip audits or browser tests.
