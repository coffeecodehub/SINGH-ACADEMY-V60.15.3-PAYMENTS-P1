# V60.11 — Actual QA report and verification limits

## Basis and scope

Base: `Singh-Academy-V60.10.zip` supplied in this conversation. The user's error trace identifies href and auth-placeholder differences at `SiteHeader.tsx`; screenshots show logout navigation getting stuck and a login form with a Back button. Inspection found multiple concrete causes; a screenshot alone cannot prove every reported payment/media delay had the same cause.

This patch preserves the custom Next 15 / React 19 / Express auth and payment architecture. It is not a framework migration, a penetration-test certificate, a production uptime claim, or a guarantee of zero latency.

## Confirmed code defects and corresponding changes

1. **Implicit form submission:** `BackButton` lacked `type="button"`. Inside the login form it could submit browser-autofilled credentials. The fixed auth Back button never submits; its destination is `/` rather than history.
2. **Hydration timing:** live auth/context/cache values and a root `Fragment` keyed by user identity could change/remount delayed server-rendered consumers before their hydration. An immutable request seed + `useSyncExternalStore` server snapshot preserves each consumer's first rendered HTML, then exposes the current state. CMS content and portal-dependent image URLs use the same hydration discipline. No mismatch is suppressed and SSR is not disabled globally.
3. **Conflicting navigation:** header, access gate and login effects could compete during auth changes. Auth document replacement has one owner per operation. Private page state is keyed by owner; the whole root layout is not.
4. **Credential/logout race:** pending login Set-Cookie could arrive after logout. Per-portal auth writes now settle in order, and explicit logout fences late identity responses. Both login-before-logout and logout-before-login sequences are tested.
5. **Landing/default return:** already authenticated root/auth-page requests now go to `/home` or the validated intended student path. Guest root stays public. Encoded `next` addresses retain queries without becoming open redirects.
6. **PayPal timer:** the HTTP timeout was created before awaiting OAuth. OAuth preparation and the actual order HTTP request now have separate time budgets; simultaneous token loads are single-flight and keyed by environment/credentials.
7. **Lost checkout-creation response:** the frontend now performs an owner-scoped READ of the same idempotency key, never automatic creation with a replacement key. No capture or access grant occurs in the new recovery endpoint.
8. **Video readiness:** supported visible recorded players can prepare paused behind their poster. Native metadata preparation and per-lesson zero-time reset are preserved; provider-origin/source checks protect postMessage handling.
9. **Feedback/footer:** immediate non-mutating navigation feedback, bounded slow-state options, and appended footer-only layout refinement. Original public CSS prefix and protected certificate assets stay byte-identical.

## New actual Next browser suite to run locally

`frontend/ui-tests/auth-hydration-v60-11.spec.ts` + `scripts/start-ui-stack.mjs` run actual Next middleware/pages/React over a loopback synthetic API. The suite checks guest hydration, slow-server/fast-browser auth, login return paths, autofilled Back without login submission, logout from Events, Back/refresh, sibling-tab logout and mobile behavior. External network is blocked for these synthetic browser cases.

This is separate from the 264 controlled reliability checks and the 144 header layout fixtures. Passing those is not substituted for this browser suite.

## Important semantics / retained safeguards

- No UI call can grant course access based only on redirect, client price, localStorage or a checkout read. Provider signature/amount/currency/ownership/idempotency checks remain authoritative.
- A failed logout denies this browser immediately and shows an honest pending server-revocation warning. It is not reported as a successful server logout.
- A real subsequent explicit credential submission may intentionally sign in again. Back/navigation never submits credentials.
- Staff/student portals remain separate. Shared published CMS cache never stores private learning/billing/certificate data.
- Expiry/security rules for existing sessions remain; normal navigation is not a promise of infinite login lifetime.
- Login/logout use one document replacement at the credential boundary to clear old RSC/router state. Normal navigation remains client-side.
- Payment/provider/media/network time is not guaranteed. Reduced duplicate work, preparation and truthful progress are not 'instant external payment' claims.
- No schema migration, no enrollment reset, no changes to actual membership entitlement timestamps, and no changes to stored certificate PDFs.
