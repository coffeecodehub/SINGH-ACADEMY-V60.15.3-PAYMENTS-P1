## Changes and rationale verified against base source

1. Lesson and admin-preview iframe markup duplicated modern fullscreen permission with the legacy fullscreen attribute. Removed only the redundant attribute, retaining fullscreen permission.
2. The old player marked iframe DOM load as usable media before a provider-ready event. Ready/playing/buffering/error events now update the existing frame. A bounded handshake recovers a missed ready event; message acceptance checks exact frame identity and exact provider origin. Initial URL start0/unlisted Vimeo hash behavior is retained. No seeking during preparation and no vendor warning filtering.
3. Course-card priority previously used the generic `100vw` default. Cards now pass sizes matching their existing grid. First3 course and first4 team images are eager/high priority. No restyling, no waiting for every image before rendering the page.
4. Catalog data was warmed without warming photos. Now public first-row photo URLs use the same srcset/sizes in a small foreground-only budget (2active,8active+queued,12remembered). External signed URLs, staff/download/API-private paths are not speculatively warmed. Checkout/learning/billing are excluded from catalog warming.
5. Image transforms previously returned an original immediately when two jobs were busy. New two-worker queue waits at most2s for admission, has max12waiting and then falls back to the already-authorized original. Shared source bytes avoid multiple GridFS downloads for different widths of the same public photo. Output and input byte caches are bounded; errors/null outcomes are not cached as successful photos. Every route still authorizes current publication/private ownership before byte-cache access.
6. Header changes apply only >=1600CSSpx: height72->80; logo48x58->52x64; brand27->29; nav12->13. Entire original CSS is an exact prefix; no other CSS changes.

Unit evidence of coalescing is one controlled original read for four requested widths. This is NOT measured live performance in milliseconds. Backend readiness, connection pools, network throughput, browser cache state and actual source files still determine latency.

## Vendor messages and limitations

The user's own stack names Vimeo `f.vimeocdn.com` and YouTube `youtube-nocookie.com`. The Chromium unload warning is consistent with the documented browser deprecation; WebGPU powerPreference is a hint, not an application request error. We did not access or modify vendor private code. These warnings may still appear even if playback is functioning. Do not suppress all console warnings or grant obsolete unload merely to get a clean console.

Actual recorded videos must be manually checked for start0, Play/Pause, Fullscreen, mobile controls and slow-network recovery after the full local gate. Live streams and external provider policies may differ from seekable recorded videos.
