# Singh Academy V59 — Connect Stripe + PayPal

The application already contains server-side hosted Stripe Checkout and server-side PayPal Orders v2 flows. The final account connection happens by adding credentials generated by the Academy's Stripe and PayPal merchant accounts.

## Production backend currently used

If the production backend remains:

```text
https://singh-academy-api.onrender.com
```

use:

```env
PAYMENT_WEBHOOK_BASE_URL=https://singh-academy-api.onrender.com
```

If the backend domain changes, replace it everywhere below.

## Stripe

1. Sign into the Academy Stripe Dashboard.
2. For testing, use Stripe test mode; for the actual production Render service (`NODE_ENV=production`), use live mode only.
3. Copy the server secret key (`sk_test_...` in test mode or `sk_live_...` in live mode).
4. Create a webhook endpoint:

```text
https://singh-academy-api.onrender.com/api/payments/webhooks/stripe
```

5. Subscribe to:

```text
checkout.session.completed
checkout.session.async_payment_succeeded
checkout.session.async_payment_failed
checkout.session.expired
refund.created
refund.updated
charge.dispute.created
charge.dispute.closed
```

6. Copy that endpoint's signing secret (`whsec_...`).

Production Render values:

```env
ONLINE_PAYMENTS_ENABLED=true
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...
```

Never put Stripe secret keys in Vercel/frontend variables or GitHub.

## PayPal

1. Sign into PayPal Developer Dashboard.
2. Open **Apps & Credentials**.
3. Create/select the Singh Academy REST app.
4. Use Sandbox credentials on staging; use Live credentials on the production service.
5. Copy the app's Client ID and Client Secret.
6. Add webhook URL:

```text
https://singh-academy-api.onrender.com/api/payments/webhooks/paypal
```

7. Subscribe to:

```text
CHECKOUT.ORDER.APPROVED
CHECKOUT.PAYMENT-APPROVAL.REVERSED
PAYMENT.CAPTURE.COMPLETED
PAYMENT.CAPTURE.DENIED
PAYMENT.CAPTURE.PENDING
PAYMENT.CAPTURE.REFUNDED
PAYMENT.CAPTURE.REVERSED
CUSTOMER.DISPUTE.CREATED
CUSTOMER.DISPUTE.RESOLVED
```

8. Save the returned Webhook ID.

Production Render values:

```env
PAYPAL_MODE=live
PAYPAL_CLIENT_ID=...
PAYPAL_CLIENT_SECRET=...
PAYPAL_MERCHANT_ID=
PAYPAL_WEBHOOK_ID=...
```

`PAYPAL_MERCHANT_ID` is optional for the current direct-merchant integration.

## Final production Render block

When both providers are ready:

```env
NODE_ENV=production
ONLINE_PAYMENTS_ENABLED=true
PAYMENTS_REQUIRE_BOTH=true
PAYMENT_WEBHOOK_BASE_URL=https://singh-academy-api.onrender.com

STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...

PAYPAL_MODE=live
PAYPAL_CLIENT_ID=...
PAYPAL_CLIENT_SECRET=...
PAYPAL_MERCHANT_ID=
PAYPAL_WEBHOOK_ID=...
```

If only one provider is ready, temporarily use:

```env
PAYMENTS_REQUIRE_BOTH=false
```

and configure only that provider. The unconfigured payment button stays disabled.

## Validate after Render redeploy

```bash
npm run payments:check -- --remote --strict-webhooks
```

No charge is created by this command. It verifies local configuration, authenticates to the providers, and checks webhook registration.

Then open the checkout page. A configured provider changes from **Not connected yet** to its active checkout label and redirects to the provider's hosted checkout page.

## Sandbox note

The current code intentionally blocks test/sandbox payment credentials when `NODE_ENV=production`. Test Stripe/PayPal on a local or separate staging backend first, then use live credentials on the production Render service.
